# ADR-004: детерминированный NL-парсер вместо внешнего LLM

## Контекст

Нужен поиск на естественном языке, который возвращает структурированный фильтр на клиенте и падает в текстовый поиск, если разбор не удался. Приложение должно подниматься одной командой в Docker, без секретов.

## Решение

`parseOrgSearch` на клиенте: тот же JSON-контракт, что вернул бы LLM (`level`, пороги, `nameIncludes`). Если ни одно поле кроме текста не распознано — `mode: "fallback"`.

## Альтернативы

- **OpenAI / Claude API.** Ближе к слову «AI», но ломает офлайн-демо, тянет ключ в `.env`, даёт латентность и стоимость.
- **Локальная модель в Docker.** Тяжёлый образ, не совместимо с лимитом бандла/«одной командой».

## Последствия

- Поиск объясним и покрыт тестами.
- Подсказка в UI явно показывает «AI-фильтр» vs «Текстовый поиск» — ревьюер видит fallback.
- Контракт фильтра можно позже подменить ответом настоящего LLM, не трогая таблицу.
