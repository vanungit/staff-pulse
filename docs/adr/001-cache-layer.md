# ADR-001: свой SWR-кэш вместо TanStack Query

## Контекст

Нужен слой запросов со stale time 5 секунд, отменой при размонтировании и инвалидацией только при реальном изменении данных. На этапе 04 production-сборка клиента должна быть ≤200 КБ gzip.

## Решение

Пишем `useCachedQuery`: in-memory `Map`, stale-while-revalidate, `AbortController`.

## Альтернативы

- **TanStack Query / SWR.** Зрелый API, девтулы, retries. Минус: +15–40 КБ gzip и ещё одна абстракция, которую на собеседовании всё равно придётся «раскрыть».
- **Простой fetch в useEffect без кэша.** Не выполняет требование про stale-while-revalidate.

## Последствия

- Плюс: полный контроль, легко объяснить, дешёвый бандл.
- Минус: нет devtools, нет общего retry/backoff (backoff появится отдельно для WebSocket на этапе 03).
- Инвалидация — явная запись в `writeQueryCache`, не по тегам запросов.
