# ADR-003: WebSocket вместо SSE и поллинга

## Контекст

Сервер должен пушить изменения метрик. Клиент применяет патч без полного рефетча и показывает статус соединения с backoff.

## Решение

Один HTTP-сервер + `ws` на `/ws`. Кадр: `{ type: "node.updated", node }`.

## Альтернативы

- **SSE.** Проще через прокси, односторонний канал достаточен. Минус: в части прокси/HTTP/2 хуже, нет симметрии с будущим ack.
- **Поллинг.** Проще в Docker/nginx. Минус: либо лаг, либо лишние запросы; ТЗ просит минимизировать их.

## Последствия

- Нужен WS-прокси в Vite и nginx (`Upgrade` / `Connection`).
- Невалидный кадр не закрывает сокет — иначе backoff зациклится на баге схемы.
- После hydrate HTTP-ревалидация не пересобирает агрегаты: источник правды — патчи.
